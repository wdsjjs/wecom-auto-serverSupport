# 新用户欢迎流程

## Summary

新添加用户进入企微后，客服系统需要先发送一套固定欢迎话术。该流程独立于普通 AI 客服回复，也独立于后续补剂推荐 Agent。

本文只沉淀新用户欢迎流程，不展开补剂推荐 Agent 的数据、规则和模型搭建方式。

标准识别场景来自企微聊天窗口中的系统文案：

```text
你已添加了 {客户昵称}，现在可以开始聊天了。
```

## 触发条件

欢迎流程在同时满足以下条件时触发：

- 最近聊天记录中出现企微系统文案 `你已添加了 ...，现在可以开始聊天了。`
- 本地欢迎状态未记录该客户已进入 `welcome_pending` 或 `welcome_sent`。
- 当前会话仍可通过现有队列和发送前复核确认是同一客户会话。

`以上是打招呼内容` 和 `你已添加了...` 都归为系统消息，不当作用户咨询内容。

## 客户标识

客户维度按以下优先级确定：

1. 优先使用企微 `external_user_id`。
2. 如果暂时未绑定 `external_user_id`，使用本地稳定的 `conversation_key` 兜底。

不得让多个未绑定新用户共用同一个全局客户 ID，避免欢迎状态和后续记忆串到其他客户。

## 状态记录

新增欢迎流程状态，按客户维度记录：

- `welcome_pending`：欢迎草稿已生成或待发送，避免重复生成。
- `welcome_sent`：欢迎话术已成功发送。
- `welcome_skipped`：欢迎草稿因上下文过期、人工跳过或其他原因未发送。

欢迎完成状态只能在发送成功后提交。生成草稿、进入审核、或发送前等待阶段都不能提前写入 `welcome_sent`。

## 回复来源

欢迎草稿使用：

```text
reply_source=welcome
```

这用于和普通 AI 回复、补剂推荐回复、人工回复区分，也方便 review 页面、指标统计和问题排查。

固定欢迎话术当前以占位模板表示：

```text
{WELCOME_MESSAGE}
```

欢迎话术缺失时，流程只能使用占位模板或配置中的固定话术，不能让模型自由编写欢迎话术。

## 欢迎流程

1. Agent 扫描到未读会话并打开聊天。
2. 读取最近聊天记录。
3. 识别新添加系统文案 `你已添加了 {客户昵称}，现在可以开始聊天了。`
4. 按客户标识查询欢迎状态。
5. 如果没有 `welcome_pending` 或 `welcome_sent`，生成固定欢迎话术草稿。
6. 草稿进入现有队列的 `ready` 状态；review 模式下等待人工审核。
7. 发送前重新打开会话复核，确认仍是同一客户会话。
8. 发送成功后记录 `welcome_sent`。
9. 如果发送前客户又发新消息导致上下文变化，欢迎草稿标记为跳过或重新排队，不提前写入 `welcome_sent`。

欢迎话术仍走现有发送路径，支持 `dry-run`、`review`、`auto`，并保留发送前复核。

## 边界规则

- `以上是打招呼内容` 不是客户咨询，不触发普通 AI 回复。
- `你已添加了...` 是新用户系统事件，不触发普通 AI 回复。
- 用户第一句打招呼，例如 `我是三水儿`，可以进入上下文，但不触发补剂推荐。
- 如果新用户首句同时包含明确补剂推荐意图，欢迎话术后可以衔接基础信息询问；该衔接规则后续在补剂推荐 Agent 方案中细化。
- 同一客户已有 `welcome_pending` 或 `welcome_sent` 时，不再生成欢迎草稿。

## Test Plan

- 系统文案识别测试：能识别 `你已添加了 三水儿，现在可以开始聊天了。`
- 防重复测试：同一客户已有 `welcome_sent` 时不再生成欢迎。
- 发送成功提交测试：只有发送成功并进入完成状态后才写入 `welcome_sent`。
- 上下文过期测试：发送前客户新发消息时不提交欢迎完成状态。
- Review 流程测试：欢迎草稿可展示、审批、发送，且 `reply_source=welcome`。
- 未绑定用户测试：无 `external_user_id` 时使用 `conversation_key` 独立记录。

## Assumptions

- 固定欢迎话术后续补充，当前文档先以 `{WELCOME_MESSAGE}` 占位。
- 本文只描述新用户欢迎流程；补剂推荐数据和 Agent 搭建方式下一步单独梳理。
