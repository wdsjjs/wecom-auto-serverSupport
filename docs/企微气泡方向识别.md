# 企微气泡方向识别

Mac 边缘通道使用 AX 获取消息正文与行结构，使用 ScreenCaptureKit 获取企微窗口帧并核对可见文本气泡的左右位置。每次 `chat` 读取只取一帧，在本机内存中分析，不运行 OCR、不调用模型、不保存窗口图像。

消息、滚动区边界和空图片行共用一份 AX 快照，避免额外执行 `geometry` 和 `chat-all` 全树扫描；取帧后的校验直接重读已定位的消息表和选中会话行。

## 运行条件

- macOS 14 或更新版本，具备 Swift 编译工具。
- 运行进程具有辅助功能和屏幕录制权限。
- 企微聊天窗口处于可采集状态。窗口被遮挡时可取帧；隐藏、最小化或台前调度移出后不保证可用。
- 辅助程序在首次读取或 Swift 源码更新后自动编译到 `wecom-gui/.codex-run/ax_wecom`。
- 本次变更默认启用方向核对。启动、停止仍由 `wecom-supervisor` 管理；采集过程不启动本地 AI。

## 判定与上报

| 证据 | 本机方向 | 中台事件 |
| --- | --- | --- |
| AX 正文匹配到靠左气泡 | 用户 / high | inbound_message |
| AX 正文匹配到靠右气泡 | 客服 / high | outbound_message |
| 命中已登记的中台发送回显 | 已发送消息 | 沿用原有回显去重，不另建人工出站消息 |
| 未匹配、零宽、屏外、取帧失败或布局变化 | unknown / low | unknown_message，继续待确认 |

方向证据位于 `message.direction_evidence`，包含 `source`、`status`、`side`，匹配成功时还有 `bubbleRect`。`high` 是离散的证据等级，不是统计准确率。

只核对单个正文节点的普通文本气泡；图片、卡片、引用等未支持布局保持待确认。判断气泡左右使用聊天滚动区边界，不使用消息集合中最左/最右文本建立阈值，也不根据文案猜测发送者。取帧前后核对选中会话、窗口、消息和坐标，变化时废弃本轮方向证据。

AX 的日期标签与正文分别提取。为兼容已经建立的观察基线，`identity_text`、`identity_time` 保留原格式供去重使用，展示正文使用清理后的 `text`。同文案不同消息保留各自出现序号；同一条 unknown 后续确认方向时复用消息 ID 和事件 ID。观察基线内的历史消息不会因本次修复自动重发。

读取到的新客户消息和人工回复都参与归档，不再因为同批消息中已有客服回复而跳过前面的客户消息。屏外消息仍保留文本候选，但其未布局坐标不参与方向计算，需后续可见时再确认。

本次不改变切换会话和发送时的 GUI 操作策略，不保证整个通道运行期间始终不抢前台，也不自动更正中台已有的错误方向。

## 验证

```sh
cd wecom-gui
python -m pytest cli_anything/wecom_gui/tests/test_bubble_geometry.py \
  cli_anything/wecom_gui/tests/test_macos_backend.py \
  cli_anything/wecom_gui/tests/test_edge_channel.py \
  cli_anything/wecom_gui/tests/test_state.py \
  cli_anything/wecom_gui/tests/test_inbox_reply_cli.py -q
```

原生图像测试会编译真实 Swift 辅助程序，使用合成图片验证左右、双倍像素比例、负坐标、零宽、视口外和左右不明确的气泡，不操作企微。单元测试另覆盖同文案、时间标签、首次基线以及没有新消息时 unknown 补确认。

2026-09-09 本机验证：137 项回归通过。新辅助程序实时识别过 7 条可见短消息（5 左、2 右）；另一次完整读取获取 20 条 AX 文本候选，正确核对当时可见的 3 条消息，其余 17 条保留待确认，完整耗时 5.55 秒。该耗时包含 AX 读取和取帧前后校验，不等同于约 0.1 秒的单次窗口取帧耗时；未做持续负载基准。

只读排查可运行 `.codex-run/ax_wecom chat` 查看原始正文和 `directionEvidence`。该命令会读取客户文本，输出仅用于本机排查。
