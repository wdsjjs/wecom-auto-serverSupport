# 企微气泡方向识别

Mac 边缘通道使用 AX 获取消息正文与行结构，使用 ScreenCaptureKit 获取企微窗口帧并核对可见文字、图片气泡的左右位置。每次 `chat` 读取只取一帧，在本机内存中分析，不运行 OCR、不调用模型、不保存方向分析使用的窗口图像；附件抓取另行处理。

消息、滚动区边界和空图片行共用一份 AX 快照，避免额外执行 `geometry` 和 `chat-all` 全树扫描；取帧后的校验直接重读已定位的消息表和选中会话行。

正常边缘采集默认取当前已加载消息表末尾 20 行，统一启动器与 `edge-channel run` 使用相同默认值。`last` 参数会传入 Swift，正文提取和取帧后校验均只读取指定范围，保留原始行号；仍需枚举行句柄来定位消息表。图片与其他消息共享这 20 行额度，不会自动向上翻历史。原生 `chat-all` 保留完整已加载表的只读排查能力。

每个消息节点通过 `AXUIElementCopyMultipleAttributeValues` 批量读取属性，一次遍历同时提取正文、时间与媒体。定位消息表时复用该轮节点数据，辅助程序使用 `swiftc -O` 编译；取帧后的校验重新读取节点，不跨轮缓存消息或方向。

## 运行条件

- macOS 14 或更新版本，具备 Swift 编译工具。
- 运行进程具有辅助功能和屏幕录制权限。
- 企微聊天窗口处于可采集状态。窗口被遮挡时可取帧；隐藏、最小化或台前调度移出后不保证可用。
- 辅助程序在首次读取或 Swift 源码更新后自动编译到 `wecom-gui/.codex-run/ax_wecom`。
- 本次变更默认启用方向核对。启动、停止仍由 `wecom-supervisor` 管理；采集过程不启动本地 AI。

## 判定与上报

| 证据 | 本机方向 | 中台事件 |
| --- | --- | --- |
| AX 正文匹配到靠左气泡 | 用户 / high | inbound_message |
| AX 正文匹配到靠右气泡 | 客服 / high | outbound_message |
| AX 图片行内唯一的图片区域靠左 / 靠右 | 用户 / 客服，high | inbound_message / outbound_message |
| 命中已登记的中台发送回显 | 已发送消息 | 沿用原有回显去重，不另建人工出站消息 |
| 未匹配、零宽、屏外、取帧失败或布局变化 | unknown / low | unknown_message，继续待确认 |

方向证据位于 `message.direction_evidence`，包含 `source`、`status`、`side`，匹配成功时还有 `bubbleRect`。`high` 是离散的证据等级，不是统计准确率。

文字只核对单个正文节点的普通气泡。图片兼容 AX 图片节点与没有正文、没有图片节点的空图片行：从聊天区外缘估计背景，提取同一帧内连续的非背景像素区域，要求区域至少为 64×64、位于对应消息行内且左右位置明确。头像大小的区域、居中图片、多个候选区域、视口边缘裁切和屏外行均不确认方向。图片证据额外携带 `method=image_pixels`，匹配到的真实区域也供附件抓取定位使用；不使用邻近文字的方向来推断图片发送者。卡片、引用等未支持布局仍保持待确认。

判断气泡左右使用聊天滚动区边界，不使用消息集合中最左/最右文本建立阈值，也不根据文案猜测发送者。取帧前后核对选中会话、窗口、本轮 20 行消息正文与顺序、可见气泡坐标，变化时废弃本轮方向证据。屏外气泡会在真实坐标与零宽占位值之间切换，这类坐标不参与一致性比较；正文变化、进出可见区域以及可见气泡移动仍会使校验失败。

文字候选颜色依据最小气泡尺寸保留，不按颜色在整屏的占比或颜色排名过滤，避免短回复和图片同屏时丢失气泡。背景颜色取聊天区外缘，避免大图片覆盖聊天区后被当作背景。候选仍需形成连续色块、完整包围 AX 正文且明确靠左或靠右；发送命令只有观察到新增出站回显才报告成功。

AX 的日期标签与正文分别提取。`identity_text`、`identity_time` 仅用于旧观察记录的升级关联；正常采集使用清理后的正文和媒体摘要做有序重叠匹配，不把方向、相对日期标签、截图路径或窗口内出现次数作为消息 ID。

### 持久化消息身份

- `edge_message_ledger` 为消息保存本机会话序号、固定事件 ID、方向和首次采集时间。每次仍读 20 行，最多与本地最近 200 条账本记录匹配，不额外读取企微历史。
- 唯一的连续重叠部分复用已有消息，只为账本尾部之后的新增部分分配 ID。同一句话在后续轮次再次出现，仍是独立消息；缩小窗口、回看历史和方向补确认不重新编号。
- 先用短事务预留消息序列和固定 ID，再将消息及待获取附件清单持久化，之后在事务外抓图。消息始终携带账本 `stream_id + sequence`；重启沿用同一来源流，重建账本才更换 stream。登记队列与附件上传分别重试，文件缺失不妨碍中台保存消息占位。
- 中台心跳声明 `deferredMediaV1` 后，使用 `messages/register` 登记消息、`messages/:messageId/media` 补齐附件；补图不改变原 ID、方向、首次观察时间及客户消息水位。未升级的中台继续走旧 `inbound-events`，本地文件缓存与缺图重试仍保留。
- 图片抓取前核对当前会话、消息快照及可见范围，屏外或变化的图片保持 `pending_media`，不盲点旧坐标。抓图失败按 2 秒起、最长 60 秒退避；抓到的附件缓存后用于网络重试，不重复打开预览。缺少文件的旧上传事件转为 `waiting_media`，补图完成后恢复同一事件；`media_capture_pending` 展示待补图数量。原始图片仍通过现有预览截图路径获取，并非下载原图。
- 升级时旧观察记录建立有序基线。只有旧哈希和首次观察时间同时对应的事件才自动继承，无法确定的旧记录不强行合并，也不再次上报；旧上传队列保持原样。已有中台重复记录不会自动删除或修正。
- 没有连续重叠、或存在多个等价匹配时，将快照存入 `edge_message_alignment_pending`，不猜测新旧、不推进尾部。状态通过 `message_alignment_pending` 计数和错误码暴露。重新读取能够衔接的历史后可继续采集；待处理快照再次读取并成功对齐后移除。目前不自动滚动补洞。
- 重叠部分连续多条只有图片占位时，即使最长匹配唯一也保留待对齐状态，避免把窗口滑动后的新图片静默当成旧图。此策略不等于已经解决图片内容身份识别；需要可区分的上下文后再恢复。图片离开 20 行窗口后仍保留登记和待获取状态，重新可见时补抓，不自动跨会话翻历史。
- 无法区分“整屏完全相同文本未变化”与“同样文本刚好替换整屏”。当前策略不凭空制造新事件；20 行之外且从未读到的消息也不承诺已采集。

读取到的新客户消息和人工回复都参与归档，不再因为同批消息中已有客服回复而跳过前面的客户消息。屏外消息仍保留文本候选，但其未布局坐标不参与方向计算，需后续可见时再确认。

### 文字提交

文字通过 AX 写入唯一匹配的主聊天输入框，再短暂激活企微并核对该输入框的焦点、内容和选中会话，向企微 PID 发送一次无修饰键的 Return。停止使用 `AXConfirm` 代替发送，也不再退回任意可编辑控件。输入框已有内容、焦点不确定或会话变化时不按回车。

输入框预检直接读取 AX 原始值，区分“读取成功且为空”“已有草稿”和“无法读取”，不使用会丢弃空字符串的消息正文辅助函数。原生脚本明确返回 `submitted=false` 时，边缘上报 `precondition_failed`；已提交或提交状态未知时才保留 `needs_reconciliation`。禁止剪贴板回退的设置同样适用于文字加图片的命令，避免预检失败后通过粘贴绕过保护。

该路径不点击鼠标，但会激活企微窗口，不能承诺完全不影响前台。图片仍沿用原粘贴及回车路径。按键提交和输入框清空都不算送达，仍由新出现的出站气泡核验；结果丢失时不自动再次提交。`wecom_text_submit` 保存脱敏动作结果，失败回执保留 `text_send:<具体原因>`。

本次不自动更正中台已有的错误方向，也不重新发送已被人工确认的命令。

## 性能与诊断

同一会话通过 `chat.read_current(last=100, capture_images=False)` 实测，包含窗口激活、AX 正文读取、ScreenCaptureKit 取帧、二次校验和 Python 解析；不包含首次编译、图片附件抓取、中台网络请求及轮询等待。

- 优化前本轮测得 4.925 秒，早前一轮为 5.55 秒。
- 优化后连续五次为 2.796、0.754、0.683、0.705、0.721 秒。首轮仍可能有启动开销，稳定后的本机样本约 0.7 秒，不能视为所有设备的延迟承诺。
- 五次均读取 20 条消息，核对相同的 3 条可见消息（2 条用户、1 条客服）；屏外 17 条保留候选。
- 定位表时不再向表内重复遍历；一次采样内复用节点属性，取帧后仍独立重读。像素分析实测约 0.01 到 0.02 秒。

设置 `WECOM_GUI_AX_PROFILE=1` 可在标准错误查看分段耗时及校验失败字段，不输出正文或密钥。例如：`WECOM_GUI_AX_PROFILE=1 .codex-run/ax_wecom chat >/dev/null`。

只读排查可运行 `.codex-run/ax_wecom chat` 查看原始正文和 `directionEvidence`。该命令会读取客户文本，输出仅用于本机排查。
